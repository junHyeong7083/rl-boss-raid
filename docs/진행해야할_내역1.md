# 진행해야할 내역 1 — 서포터 버프 역할 미수행 수정 + 재학습

> 작성: 2026-08-21 / 상태: **대기** (추후 작업)

## 문제

서포터 NPC가 버프를 거의 사용하지 않고 서브 딜러로 수렴함 (판당 버프 0.1~0.3회, 보조딜 6,400).
구모델·신모델(tankfix) 공통 — 이번 탱커 수정과 무관한 기존 보상 설계 문제.

## 원인 (탱커 어그로 문제와 동일 구조)

- 평타: 쿨 없음, 딜 보상 ≈ 24 × 0.15 = **3.6/턴** ([rewards.py](../RL_Game_NPC/src/raid/rewards.py) SUPPORT 분기 `dmg * 0.15`)
- 버프: 쿨 8턴, `rw_buff_hit = 2.5`/회 + 버프 턴엔 평타 기회 상실
- → 매 턴 평타가 버프보다 항상 이득 → 버프 안 누르는 게 최적 정책
- 증거: 학습 로그 서포터 엔트로피 ~0.3 (거의 결정론적 평타 스팸), 힐러는 2.2

## 수정 방안

1. **최소 수정**: `rw_buff_hit` 2.5 → 6~8 (평타 2턴치 이상, config.py:393 부근)
2. **원리적 수정(권장)**: 버프 지속 중 아군이 넣은 추가 딜(버프 배수분)을 서포터 보상으로 귀속
   — 버프의 실제 전투 가치를 보상에 반영. env에서 버프 활성 중 damage 이벤트에
   버퍼 uid 태깅 필요 (`_do_buff` / 데미지 처리부).
3. 버프 유지율(uptime)을 관측·지표에 추가하면 검증 용이 (논문 평가 지표 18.3에도 있음)

## 작업 순서 (탱커 때와 동일 절차)

1. 보상 수정 (config.py + rewards.py, 필요 시 env.py 버프 귀속)
2. 스모크 2,000 ep (~1.5h) → 버프 사용 횟수/uptime 확인
   - 검증 스크립트: 스크래치패드 `eval_role_behavior.py` (버프 회/판 측정) 재사용
3. 풀 재학습 20,000 ep + BC 2,000 (~10.6h, `rl_game_npc` conda env)
   - `python train_raid.py --episodes 20000 --bc-episodes 2000 --device cuda --model-dir models_raid_supfix`
4. n=120 최종 평가 + 역할 지표 비교 → 통과 시 `models_raid/final.pt` 교체 (기존 백업 유지)

## 완료 기준

- 서포터 버프 사용 ≥ 판당 5회 이상(쿨 8턴 기준 현실 상한 감안) 또는 버프 uptime 50%+
- 승률 비열등 (n=120, 65% 이상), 기믹 성공률 85%+ 유지

## 참고

- 탱커 수정 이력: 도발 어그로 탈환(`aggro_taunt_overtake` 1.10, env.py), 탱킹 피격 페널티 차등
  (`rw_tank_hit_tanking` −0.5), 결과: 어그로 1위 51→65.5%, 보스거리 3.4→2.4
- 현재 배포 모델: `models_raid/final.pt` = tankfix (백업: `final_paper_708.pt.bak`)
